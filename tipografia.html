Sistema Tipográfico

Consumo de clases utilitarias "Tokens" para aplicaciones web.

Análisis y Documentación Oficial

1.- Guía de Implementación y Modificadores

Uso de clases OOCSS: La tipografía en el ecosistema UNAV se gestiona mediante clases utilitarias estrictamente atómicas. Cada nodo de texto debe declarar explícitamente sus propiedades combinando las clases base: .unav-font-[familia], .unav-weight-[peso], y .unav-text-[escala].

Modificadores: Para controlar el flujo vertical se utilizan los modificadores de interlineado .unav-lh-[tipo] (ej. -tight, -normal, -relaxed). Está terminantemente prohibido anidar estilos tipográficos en componentes complejos; la pureza del OOCSS exige que la presentación esté completamente separada del contenedor semántico.

2.- Guía Técnica

Construcción HTML5: Utilizar etiquetas semánticas (H1-H6 para estructura jerárquica SEO, P para párrafos extensos, SPAN para alteraciones inline). La semántica del HTML no dicta su tamaño visual; un H2 puede usar la clase .unav-text-125 si el diseño modular lo requiere.

CSS y Tokens de Variables: Todo el sistema renderiza consumiendo las variables declaradas en el bloque :root de unav-styles.css (ej. var(--unav-fontSize150)). Los tamaños base están formulados en rem (escala basada en 16px). JS interviene (mediante IntersectionObserver) únicamente si hay animaciones de aparición o desvanecimiento vinculadas al scroll tipográfico.

3.- Accesibilidad (A11y) y Schema.org

Cumplimiento WCAG 2.1 Nivel AA: Todas las combinaciones de color tipográfico sobre fondos deben pasar un ratio de contraste mínimo de 4.5:1 para textos estándar (.unav-text-100) y 3:1 para textos grandes o en negrita. El uso de rem permite a los usuarios con discapacidades visuales reescalar las fuentes globalmente desde su navegador sin romper el layout.

Microdatos: Los titulares principales deben llevar el atributo itemprop="headline" o itemprop="name", mientras que los bloques de texto informativos deben emplear itemprop="description" o itemprop="articleBody", vinculados siempre a su entidad padre (ej. TechArticle, Event, Person).

4.- UX, Layout y Medios

Ritmo de Lectura (Measure): Para garantizar la fatiga visual mínima, los bloques de texto no deben exceder los 70-80 caracteres por línea en pantallas de escritorio. Combinar el tamaño base (.unav-text-100) con el interlineado (.unav-lh-normal) garantiza la proporción áurea de la lectura corporativa.

Textos sobre Medios (Imágenes 16:9/Vídeos): Cuando un titular o párrafo flote sobre contenido multimedia, es imperativo garantizar la legibilidad utilizando las clases de sombra corporativa (ej. text-shadow: 1px 1px 3px rgba(0,0,0,0.6)) o mediante la aplicación de capas de contraste base (var(--unav-heroOverlayDark)).

3. Escala de Interlineado (Line Height)

El interlineado debe ajustarse según el tamaño del texto. Textos grandes requieren interlineados estrechos (Tight), mientras que párrafos pequeños requieren interlineados más amplios (Relaxed) para mejorar la lectura.

.unav-lh-tight (1.1)

Titulares Gigantes
Necesitan Espacio
Muy Reducido

.unav-lh-normal (1.5)

Este es el interlineado base estándar del sistema. Se utiliza para la lectura de párrafos convencionales. Permite que el ojo humano transite de una línea a otra sin esfuerzo, evitando la fatiga visual en textos de media y larga extensión.

.unav-lh-snug (1.25)

Interlineado intermedio ideal para subtítulos o sumarios de noticia.

.unav-lh-relaxed (1.75)

Cuando el texto es extremadamente pequeño (075), aumentamos ligeramente el interlineado para evitar que las líneas colisionen. Este comportamiento es vital en notas legales, referencias al pie o textos meta que ocupan varias líneas.

4. Enlaces Inline (Cuerpo de texto)

Los enlaces que conviven dentro de párrafos estándar (Roboto, Regular 400, 1.125rem) deben utilizar la clase .unav-enlaceInline. Esta abstracción aplica el color corporativo institucional y un subrayado desplazado (offset) que mejora significativamente la legibilidad y la accesibilidad (WCAG) sin recargar la lectura. Para fondos oscuros o corporativos, se utiliza el modificador .unav-enlaceInlineBlanco.
