Design System UNAV

Iconografía

Librerías estándar y pautas para el uso e implementación de elementos iconográficos en el ecosistema digital.

Análisis y Documentación Oficial

1.- Guía de Implementación y Modificadores

Uso de clases escalares: El tamaño de los iconos NUNCA se establece en px estáticos. Se deben consumir las clases utilitarias transversales: .unav-icono-sm, .unav-icono-md, .unav-icono-lg, y .unav-icono-xl.

Modificadores de Color: La iconografía hereda nativamente el color de su contenedor padre mediante la propiedad fill="currentColor" (SVG) o color: inherit (Fuentes).

2.- Guía Técnica

Construcción SVG: Si se usan SVGs inyectados, el viewBox debe ser estrictamente 0 0 24 24 o la rejilla proporcional oficial. Todo trazo debe estar expandido (Outline Stroke) para prevenir deformaciones al escalar.

Librerías Permitidas: Bootstrap Icons (Base estructural UI), Google Material Symbols Outlined (Infografías), y SVG Propios UNAV para logotipos e isologos de facultades o centros.

3.- Accesibilidad (A11y) y Schema.org

Iconos Decorativos vs Semánticos: Si el icono acompaña a un texto descriptivo, DEBE llevar el atributo aria-hidden="true". Si el icono es el único contenido de un botón, el botón DEBE tener un aria-label o un .unav-sr-only interno.

Microdatos: Si los iconos forman parte de un escaparate visual, se pueden etiquetar con itemscope itemtype="https://schema.org/VisualArtwork".

4.- UX, Layout y Medios

Consistencia Visual (Stroke): El sistema audita un grosor visual de aproximadamente 1.5px para estar alineado con los tokens de bordes del sistema. Evitar iconos con rellenos sólidos (Solid/Filled) a menos que representen estados activos.

Feature Boxes: Para crear bloques de características, utiliza el componente OOCSS .unav-iconoDestacado que gestiona el padding, fondo neutro y la respuesta táctil/hover.
