Design System UNAV

Listado de Noticias (8 Col)

Refinamiento del componente de lista con formato de fecha editorial y contención en grid central.

Guía Técnica y Documentación Oficial

1. Implementación OOCSS y Arquitectura

  • Estructura Global: La grilla completa debe estar contenida bajo la clase .unav-newsListContainer. Esta clase actúa como el marco de referencia espacial para el cálculo de las animaciones.
  • Módulos Internos: El listado no inventa elementos nuevos, sino que reutiliza el componente Tarjeta Modular (.unav-card) ajustado para representar noticias, garantizando el reciclaje de código y estilos visuales.

2. Guía Técnica (JavaScript y Staggering)

  • Motor de Animación (JS): Implementa un IntersectionObserver avanzado. A diferencia de otros componentes, calcula el retardo usando módulo matemático (index % 5) * 100, lo que significa que la onda visual se reinicia cíclicamente para evitar esperas eternas en listados masivos.
  • Gestión de Clases: Las tarjetas nacen con .unav-efectoEntradaOculto (traslación inferior y opacidad 0) y el observador muta su estado inyectando .unav-efectoEntradaVisible de forma controlada.

3. Accesibilidad (A11y) y Schemas (SEO)

  • Microdatos de Noticias: Cada iteración del listado es un organismo en sí mismo y debe encapsularse en itemscope itemtype="https://schema.org/NewsArticle". Es vital declarar las propiedades headline, datePublished y image.
  • Accesibilidad Semántica: Las fechas de las noticias deben usar el nodo nativo <time datetime="YYYY-MM-DD">. Los enlaces de "Leer noticia" deben abarcar toda el área interactiva de la tarjeta para evitar redundancia focal en el lector de pantalla.

4. UX, Uso de Átomos y Medios

  • Agrupación de Átomos: Este layout consume los átomos de Etiquetas (.unav-tag) para categorizar la actualidad (ej. "Investigación", "Deportes") y bloquea la altura tipográfica para que los títulos truncados no rompan la grilla.
  • Rendimiento de Imágenes: En un listado de noticias el peso de descarga puede ser crítico. Las miniaturas exigen formato WebP, relación de aspecto 16:9 y carga diferida (loading="lazy"), con resolución máxima recomendada de 600px de ancho por imagen.
